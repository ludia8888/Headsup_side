## 구현한 사용자 흐름

캐릭터 이름과 3가지 성격 선택 → 실제 개별 앱 선택 → 앱별 하루 한도 → 먼저 전화하는 약속 → 마이크/알림 설명·허용 → 시험 통화입니다. 앱 목록을 열기 위한 FamilyControls 권한은 앱 선택 버튼에서 필요한 설명과 함께 요청합니다. 선택 토큰으로 앱 이름을 추정하거나 고정된 Instagram 버튼을 실제 감지 설정인 것처럼 사용하지 않습니다.

홈은 캐릭터와 관계에 집중합니다. ‘우리’에는 직접 확인한 기억과 수정·삭제를, ‘설정’에는 앱별 하루 한도·재전화·성격·목소리·호칭·오늘 쉬기를 둡니다. 성격·기억의 변경은 다음 통화에 반영하도록 서버의 진행 중 통화 설정을 고정합니다.

최신 제품 방향은 ‘매번 다른 재미있는 전화로 사용 흐름 전환’입니다. 감지는 연락 타이밍에만 쓰고, 첫마디는 인사·이유 설명·잔소리 없이 답하기 쉬운 한 문장으로 시작하도록 설정했습니다. 24개의 짧은 질문에서 최근 12개와 직전 종류를 피하며 무작위로 고르고, 서버가 선택한 정확한 질문을 앱의 첫 음성 지시에도 전달합니다. 그 뒤 AI가 선택한 성격과 답변에 맞춰 즉흥적으로 전개합니다. 같은 전화의 재요청/조회와 실제 세션 설정에 동일한 소재가 들어가는 것은 서버 자동 검사로 확인했습니다. 실제 모델이 그 문장을 첫 음성으로 말했는지, 사용자가 흥미를 느꼈는지, 앱 사용이 줄었는지는 아직 검증하지 않았습니다. 한 번 답하고 끊어도 되며 20분 동행은 사용자가 먼저 원할 때 이어집니다.

이번 변경에서 통화 기록에 `받기 → WebRTC 준비`, `받기 → 첫 AI 발화 신호`, `받기 → 첫 원격 음성 패킷`, `첫 AI 발화 신호 → 첫 사용자 발화 신호` 시간을 각각 기록하도록 했습니다. 시각만 기기에 저장하고 말한 내용은 저장하지 않습니다. 첫 사용자 발화 신호는 질문에 흥미를 느꼈다는 증거가 아니므로, 통화 후 선택 가능한 ‘첫마디가 답하고 싶어졌나요?’ 자기보고를 별도로 받습니다. RTP 패킷 수신도 실제 스피커에서 들린 증거가 아닙니다.

사용 시간 권한 없이도 ‘수동 통화부터 시험하기’로 진행할 수 있도록 분리했습니다. 감지 설정을 마쳐야만 음성 시험을 할 수 있는 구조가 아닙니다.

첫 전화가 거절되거나 부재중으로 끝난 뒤에만 새 추가 사용 이벤트를 시작합니다. 기본 20분은 벽시계 경과가 아니라 **같은 앱 추가 사용**입니다. 앱별 하루 최대 두 번, 받았다면 해당 앱 당일 억제, 통화 중 감지 버리기, 한도 수정 시 당일 기록 보존을 구현했습니다. 모든 기기 안의 변경은 앱·확장 기능에서 같은 파일 잠금을 사용합니다.

설정의 ‘오늘은 쉬기’는 이제 ‘오늘 다시 전화받기’로 취소할 수 있습니다. 쉬는 중 이미 넘긴 첫 한도를 다시 평가하되 기존 통화 시도 횟수는 보존합니다. 취소 후 재전화가 필요하면 추가 사용 시간은 취소 시점부터 다시 셉니다. 첫 현장 시험에서는 사용자가 버튼을 여러 번 눌러 다시 쉬기 상태가 되었고, 요청은 서버와 iPhone까지 도착했으나 수신 직후 `failed`로 종료됐습니다. 이에 서버의 쉬기 상태를 먼저 해제·확인한 뒤 한도를 재평가하고, 중복 탭을 막기 위해 버튼을 30초간 잠그며, 화면에 뜨기 전 실패한 시도는 남은 일일 한 번으로 재시험할 수 있게 수정했습니다. 두 선택 앱 모두 1분으로 설정된 iPhone에 수정 빌드를 설치했고, 재시험에서 자동 전화 수신·받기 후 사용자가 직접 끊은 결과를 확인했습니다. AI 음성은 이 통화에서 시작되지 않았습니다.

기억 후보는 기기에 영구 저장하지 않습니다. 확정 목록에는 명확한 음성 동의 또는 확인 버튼으로 수락한 내용만 넣습니다. GPT-Live는 문장 완료 신호 없이 음성 문자 조각을 보내므로 **질문과 대답의 음성 타임라인, 1.2초의 안정 구간, “기억해 줘/저장해 줘”라는 분명한 표현**을 함께 확인합니다. 지연된 과거 ‘응’, 겹친 말, 뒤늦은 부정 정정은 저장하지 않도록 자동 검사했습니다. 실제 통화에서의 정확도는 아직 미확인입니다.

## 실제 통화 준비와 승인 잠금

UI 개편의 기준, 수정 내역, 실제 검토 범위와 화면은 [최신 v2 제작 기록](UI_REDESIGN_V2.md)에 별도로 남겼습니다. 수신/연결 중/대화/동행 상태를 구분해 표시합니다. 시뮬레이터에서는 CallKit 수신이 바로 종료되어 앱 안 수신 화면을 사용하도록 수정했습니다. 초기 GPT-Live 연결의 SDP 끝 CRLF 누락도 서버에서 보정했습니다. 이후 실기기 수동 통화에서 시스템 전화 알림·실제 음성 연결·종료가 사용자와 서버 기록으로 확인됐습니다.

수동 통화 경로에는 실제 CallKit과 네이티브 WebRTC 코드가 있으며 서버가 GPT-Live의 SDP answer를 받아 연결합니다. `gpt-live-1`은 자연스러운 음성 대화, `gpt-6-luna`는 필요할 때 위임받은 기억·동행·연락 중단 작업을 맡습니다. 종료 시 Live가 확인해 준 사용 초 수만 기록하고, 확인이 없으면 확정하지 않습니다. 모형 AI 음성을 들려주거나 API 실패를 연결 성공으로 바꾸지 않습니다. 실기기 수동 음성과 명시적 Sandbox APNs 잠금 화면 수신은 확인됐습니다. 사용 시간에서 시작된 자동 수신은 아직 확인되지 않았습니다.

후속 요청에 맞춰 `server/scripts/configure-openai.mjs`와 [비공개 키 입력 화면](http://127.0.0.1:8788)을 추가했습니다. API 키는 채팅·명령 인자·소스 코드에 넣지 않고 입력창 또는 사용자가 지정한 키 파일로 받습니다. 실제 키로 `gpt-live-1`과 `gpt-6-luna`의 모델 조회 접근을 확인한 뒤 `.env`에 저장하고 서버를 재시작했습니다. 입력창의 키 값은 제출 직후 지우며 상태 응답과 로그에는 키 값을 포함하지 않습니다. 모델 조회 성공만으로 WebRTC 통화 성공을 판단하지 않습니다.

실제 앱 연결 시험에서 서명 없는 시뮬레이터의 Keychain 오류 `-34018`을 발견했습니다. Xcode의 로컬 실행용 서명으로 다시 빌드·설치한 뒤 Keychain 저장과 재실행 후 인증 사용을 확인했습니다. 서명 방식 변경으로 기존 캐릭터·온보딩 설정이 다른 저장소로 바뀌지 않도록 시뮬레이터 저장 위치도 고정했습니다. iPhone은 기존의 서명된 App Group과 공유 Keychain을 사용합니다.

Xcode의 `Jimin` Debug 구성에서만 앱·확장 기능의 승인 플래그와 참조값을 켰고, 비공개 시험 서버 설정도 열었습니다. Release 구성은 꺼져 있습니다. 개발자 본인의 공식 회신 수령 보고를 근거로 한 시험이며, 원문·허용 범위는 독립적으로 확인하지 못했습니다. 잠금 상태에서 VoIP가 앱을 새로 실행할 때 Family Controls가 일시적으로 `notDetermined`를 반환해 저장된 승인을 지우거나 통화를 닫지 않도록 수정했습니다. 명시적으로 `denied`가 반환되면 차단합니다.

화면 잠금이나 긴 침묵에서 실제 양방향 통화가 유지되는지, 강제 종료 상태에서 전화가 도착하는지, 이벤트부터 수신까지 얼마나 지연되는지는 미확인입니다. OS 동작을 항상 전체 화면/즉시 도착으로 약속하지 않습니다.
